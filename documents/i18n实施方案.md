# VisionPass 国际化 (i18n) 全栈实施方案

> **文档定位**：本文档为 VisionPass 项目引入多语言支持（i18n，首期支持 `zh-CN` 简体中文与 `en-US` English）的完整技术方案与实施规范。旨在兼顾 TanStack Start SSR/CSR 全栈架构、保持极低包体积与高性能、提供零运行时开销的 TypeScript 类型安全推导，并确保持久化与语言自动检测无缝衔接。

---

## 一、需求背景与目标

### 1.1 背景
VisionPass 是一个基于端侧 ORB 特征提取与服务端几何一致性比对的物理密语开源系统。当前版本（v6.0）全站界面文案（包括首页愿景、Playground 体验工坊、技术白皮书、直达验证页及各 UI 状态提示）均硬编码为简体中文。为了方便全球开源开发者、极客及海外用户体验与共同构建，需要建立高品质的多语言国际化体系。

### 1.2 核心目标
1. **轻量与高内聚**：不引入重量级过度封装的外部库（如臃肿的多插件生态），采用轻量级、响应式、类型安全的 i18n 状态与资源管理。
2. **SSR / Hydration 一致性**：支持 Cookie 与 LocalStorage 双重持久化，服务端预渲染能正确读取 Cookie 中的语言偏好，避免客户端 Hydration 错位与闪烁（FOUC）。
3. **全栈类型安全与补全**：字典定义具备严格的 TypeScript 类型约束（自动推导出翻译键名联合类型），确保开发期间拼写错误在编译期即可拦截。
4. **动态与结构化内容支持**：支持插值参数格式化（如 `{count}`、`{version}`）、富文本段落及白皮书文档结构的多语言翻译。
5. **无感知平滑切换**：提供全局语言切换器组件（置于顶部 Header 与移动端菜单），切换后即时更新整站文案，并在页面重载与路由跳转时保持状态。

## 二、技术选型与架构设计

### 2.1 方案对比与选型

| 方案 | 优点 | 缺点 | 选型结论 |
| :--- | :--- | :--- | :--- |
| **react-i18next / i18next** | 功能丰富、生态大 | 依赖多、包体积大、SSR/Server Function 环境配置复杂 | ❌ 不推荐 |
| **next-intl / react-intl** | FormatJS 生态标准 | 针对 Next.js 设计，TanStack Start 适配存在胶水层冗余 | ❌ 不推荐 |
| **轻量级 React Context + TypeScript Typed Dictionary 方案** | 零冗余依赖、体积 < 2KB、100% 类型安全、完美契合 TanStack Start、SSR/CSR 自由掌控 | 需手写轻量 Context 与 Cookie 同步 | **✅ 最佳实践 (推荐采用)** |

### 2.2 语言模型与支持列表

首期支持以下两种语言（后续可轻松横向扩充日语 `ja-JP` 等）：
- `zh-CN`: 简体中文 (Default)
- `en-US`: English

```ts
export type SupportedLocale = 'zh-CN' | 'en-US'
export const DEFAULT_LOCALE: SupportedLocale = 'zh-CN'
export const SUPPORTED_LOCALES: { code: SupportedLocale; label: string; flag: string }[] = [
  { code: 'zh-CN', label: '简体中文', flag: '🇨🇳' },
  { code: 'en-US', label: 'English', flag: '🇺🇸' },
]
```

### 2.3 语言解析与持久化策略（优先级从高到低）
1. **URL 参数 / 路由上下文（可选覆盖）**：如 `?lang=en-US`（主要用于外链分享调试）。
2. **Cookie `visionpass_locale`**：服务端 SSR 解析首选，避免水合不一致。
3. **客户端 `localStorage.getItem('visionpass_locale')`**：持久化备份。
4. **浏览器环境标头 `navigator.language` / `Accept-Language`**：自动匹配前缀（如 `en-*` 映射到 `en-US`，`zh-*` 映射到 `zh-CN`）。
5. **保底语言**：`DEFAULT_LOCALE` (`zh-CN`)。

## 四、核心接口与类型设计

### 4.1 字典结构 Schema 设计（`src/i18n/types.ts`）

定义基准字典结构（以 `zh-CN` 为 Base Type），英文字典必须与其完全同构：

```ts
import type zhCN from './locales/zh-CN'

export type TranslationSchema = typeof zhCN

type Join<K, P> = K extends string | number
  ? P extends string | number
    ? `${K}.${P}`
    : never
  : never

export type NestedKeyOf<ObjectType extends object> = {
  [Key in keyof ObjectType & (string | number)]: ObjectType[Key] extends object
    ? `${Key}` | Join<Key, NestedKeyOf<ObjectType[Key]>>
    : `${Key}`
}[keyof ObjectType & (string | number)]

export type TranslationKey = NestedKeyOf<TranslationSchema>

export interface I18nContextValue {
  locale: SupportedLocale
  setLocale: (locale: SupportedLocale) => void
  t: (key: TranslationKey, params?: Record<string, string | number>) => string
  dict: TranslationSchema
}
```

### 4.2 翻译插值与访问器实现（`src/i18n/context.tsx`）

```tsx
import React, { createContext, useContext, useState } from 'react'
import { DEFAULT_LOCALE, type SupportedLocale, type TranslationKey, type I18nContextValue } from './types'
import { getDictionary } from './locales'

const I18nContext = createContext<I18nContextValue | null>(null)

export function I18nProvider({ 
  initialLocale = DEFAULT_LOCALE, 
  children 
}: { 
  initialLocale?: SupportedLocale
  children: React.ReactNode 
}) {
  const [locale, setLocaleState] = useState<SupportedLocale>(initialLocale)

  const setLocale = (newLocale: SupportedLocale) => {
    setLocaleState(newLocale)
    if (typeof window !== 'undefined') {
      localStorage.setItem('visionpass_locale', newLocale)
      document.cookie = `visionpass_locale=${newLocale};path=/;max-age=31536000;SameSite=Lax`
      document.documentElement.lang = newLocale
    }
  }

  const dict = getDictionary(locale)

  const t = (path: TranslationKey, params?: Record<string, string | number>): string => {
    const keys = path.split('.')
    let current: any = dict
    for (const key of keys) {
      if (current && typeof current === 'object' && key in current) {
        current = current[key]
      } else {
        return path
      }
    }
    if (typeof current !== 'string') return path
    
    if (params) {
      return Object.entries(params).reduce((str, [k, v]) => {
        return str.replace(new RegExp(`\\{${k}\\}`, 'g'), String(v))
      }, current)
    }
    return current
  }

  return (
    <I18nContext.Provider value={{ locale, setLocale, t, dict }}>
      {children}
    </I18nContext.Provider>
  )
}

export function useI18n() {
  const ctx = useContext(I18nContext)
  if (!ctx) throw new Error('useI18n must be used within an I18nProvider')
  return ctx
}

## 七、注意事项与最佳实践

1. **英文长文本布局自适应**：
   - 英文在按钮和标语中往往占用更多水平宽度。Tailwind 类名需避免固定写死 `w-[xxxpx]`，建议采用 `min-w-fit`、弹性伸缩与合理的 `text-sm sm:text-base` 响应式字号。
2. **文档 Markdown / 富文本处理**：
   - 白皮书中的技术名词（如 `ORB`, `RANSAC`, `Lowe's Ratio`, `Homography`, `DLT`）英文版保持标准学术术语，中文版保留原名词并附中文解释。
3. **零影响核心视觉计算**：
   - i18n 仅作用于 UI 渲染层，Web Worker 计算与 Server Functions 传递的特征协议（`OrbFeaturePayloadV1`）严格保持纯英文字段，不受任何语言设置影响。
```
