# 重构实施方案 v5.0（TanStack Start 全栈重构：Server Functions 驱动的 MVP）

## 0. 文档定位与重构目标

本方案指导 VisionPass 从 **Vite SPA + Vercel Functions (/api 目录)** 架构全面升级为 **TanStack Start (基于 Nitro / Vinxi / Vite) 现代全栈架构**。

### 核心演进诉求：
1. **移除独立 `api/` 目录**：彻底消除 Serverless 独立部署引起的文件打包割裂与 `ERR_MODULE_NOT_FOUND` 模块丢失问题。
2. **全量接入 TanStack Start Server Functions (`createServerFn`)**：
   - 凭证创建 (`createCredentialFn`)
   - 凭证元数据查询 (`getCredentialMetaFn`)
   - 图像特征比对验证 (`verifyCredentialFn`)
3. **实现前后端同构与零心智负担共享**：
   - Schema（Zod `OrbFeaturePayloadSchema`、`MATCH_CONFIG` 等）在前端与 Server Functions 之间无缝直接引用。
   - 数据库客户端 (`db`)、匹配器算法 (`orb-basic.ts`) 统一放置于 `src/server/` 或 `src/lib/`，享受 Nitro 统一打包与 Tree-shaking 保护。
4. **端到端类型安全 RPC**：
   - 前端通过 TanStack Query 直接调用类型安全的 `createServerFn`，不再手动拼接 `fetch('/api/...')` URL 字符串与处理序列化样板代码。

## 1. 范围与边界控制（MVP）

### 1.1 必须实现
- **全栈框架**：TanStack Start (React 19 + TypeScript + Bun + Vite)。
- **路由系统**：基于 TanStack Router 的全栈文件路由与布局系统。
- **服务端通信**：纯 `createServerFn`（无独立 REST API 路由文件）。
- **浏览器端处理**：OpenCV.js 异步预热/预加载，最长边 640px 灰度化 resize，ORB 描述子与关键点提取。
- **服务端处理**：PostgreSQL 存储 + Drizzle ORM，纯 TypeScript Brian Kernighan Hamming 位运算匹配。
- **部署平台**：一键部署至 Vercel（通过 Nitro 自动适配）。

### 1.2 明确不做（维持 MVP 极简原则）
- 不引入摄像头连续扫码、Passcode 手动输入或 OCR。
- 不引入服务端 OpenCV 原生模块或 Python 进程。
- 不引入多参考图、pgvector 向量库、全库图像检索。
- 不引入 RANSAC homography（保留独立匹配器模块，后续无缝升级）。
- 不引入账户体系、OAuth、Redis 或消息队列。

## 4. Server Functions 接口协议

所有端点均使用 `createServerFn` 声明，强类型约束输入输出：

### 4.1 创建凭证 `createCredentialFn`
- **Method**: `POST`
- **Input**: `{ secret: string, feature: OrbFeaturePayloadV1 }`
- **Output**: `{ token: string, readUrl: string }`
- **流程**:
  1. Zod 严格校验密语与特征 Payload。
  2. 生成 CSPRNG 16 字节 Base64url 安全 Token。
  3. 持久化到 PostgreSQL。
  4. 返回读取链接 `${APP_ORIGIN}/r/${token}`。

### 4.2 查询凭证状态 `getCredentialMetaFn`
- **Method**: `GET`
- **Input**: `{ token: string }`
- **Output**: `{ exists: boolean }`
- **流程**:
  1. 查询数据库是否存在对应 Token。
  2. 仅返回布尔值，绝不暴露密语或特征集。

### 4.3 比对验证凭证 `verifyCredentialFn`
- **Method**: `POST`
- **Input**: `{ token: string, feature: OrbFeaturePayloadV1 }`
- **Output**: `{ matched: true, secret: string } | { matched: false }`
- **流程**:
  1. 校验输入 Payload 合规性。
  2. 从数据库读取该 Token 的参考特征 Payload。
  3. 调用 `matchOrbBasic` 执行暴力 Hamming 匹配。
  4. Good match 达到阈值（≥ 25）则返回密语，否则拒绝。

## 5. 实施里程碑计划

### Milestone 1: 依赖与配置升级
- 引入 `@tanstack/react-start`、`@tanstack/start-server-functions`、`@tanstack/react-router` 及对应打包支持。
- 配置 `app.config.ts` / Nitro 适配器，移除独立的 `api/` 目录与 Vite 自定义 API 中间件。

### Milestone 2: 服务端逻辑重构为 `createServerFn`
- 在 `src/server/functions/credentials.ts` 中实现三个核心 `createServerFn`。
- 直接引用 `src/server/db` 与 `src/lib/feature-schema`，享受同仓同构编译。

### Milestone 3: 路由体系与 UI 迁移
- 迁移 `/create` 与 `/r/$token` 页面为 TanStack Router 约定路由。
- 将页面内部旧有的 `fetch` 替换为直连 `createCredentialFn`、`getCredentialMetaFn`、`verifyCredentialFn`。

### Milestone 4: 规范校验与 Vercel 部署验证
- 运行 Biome 校验与类型检查。
- 部署至 Vercel 验证 Server Functions 自动生成与全流程闭环（创建 -> 生成 QR -> 同图验证通过 -> 异图验证拒绝）。
